# Архитектура «хаба» для Zapret2 + TG WS Proxy + стратегий

Дата: 21.11.2026. Статус: предложение (обсуждение до старта разработки).

## 1. Цели и ограничения

Требования:
1. Работает не только на этом ПК (установщик, без dev-окружения).
2. Максимально мало весит, **один** установочный файл.
3. Мало потребляет память/CPU в фоне.
4. Само обновляет компоненты (Zapret2, TG WS Proxy, списки, стратегии).
5. **Никаких отдельных иконок в трее** — все компоненты как плагины внутри хаба.
6. Стратегии подтягиваются из Zapret2 GUI и CDPI-паков; паритет по фильтрам/настройкам.
7. Минимум переделок: изменения поведения — через манифесты/данные, а не код.

Ключевое наблюдение: сетевую работу делают `winws.exe`/`winws2.exe` и `TgWsProxy`.
Наш продукт — оркестратор: UI + процессы + обновления + каталог стратегий.
Поэтому «скорость языка» — вторична; важнее размер, стабильность и скорость итераций.

## 2. Рекомендуемый стек

**Rust + Tauri v2** (бэкенд Rust, UI на Svelte/TypeScript).

| Критерий | Rust + Tauri | Go + Wails | C# + Avalonia | Rust + Slint |
|---|---|---|---|---|
| Размер установщика | ~10–15 МБ | ~10–15 МБ | ~30–70 МБ (AOT/self-contained) | ~5–8 МБ |
| Память в фоне | ~10 МБ (сервис) / 60–120 МБ (UI) | ~15 / 70–120 МБ | ~10 / 100–150 МБ | ~8 / 40–60 МБ |
| Зависимости у пользователя | WebView2 (есть в Win10/11, на этом ПК 157.0.4341.60) | WebView2 | .NET Desktop Runtime (либо раздутый single-file) | нет |
| Скорость UI-разработки | высокая (веб-технологии) | высокая | средняя | низкая |
| Интеграция с Windows (сервис, WinDivert, UAC) | отлично | хорошо | отлично | отлично |
| Кроссплатформенность | Win/Linux/macOS | то же | то же | то же |

Альтернатива, если Rust «дорог» по времени: **Go + Wails** (почти те же плюсы, проще язык).
C#+Avalonia оправдан, если переиспользуем код CDPI целиком — но вес и требование .NET Runtime хуже для раздачи.

## 3. Архитектура процессов (без лишних треев)

```
┌──────────────────────────┐        named pipe / 127.0.0.1+token
│  hub-ui (.exe, по кнопке)│ ─────────────────────────────┐
│  окно + (опц.) 1 трей    │                              │
└──────────────────────────┘                              ▼
                                             ┌───────────────────────────┐
                                             │ hubd (Windows-служба)     │
                                             │ - процессы компонентов    │
                                             │ - обновления              │
                                             │ - каталог стратегий       │
                                             │ - тесты/автовыбор         │
                                             └─────┬───────────┬─────────┘
                                                   │           │
                                    winws2.exe ◄───┘           └──► TgWsProxy (headless)
                                    (WinDivert, SYSTEM)            (127.0.0.1:1443)
```

Почему так:
- Служба в SYSTEM **запускает winws2 без UAC-окна** каждую загрузку.
- Дочерние процессы службы **не создают своих треев** — TG-прокси запускается в headless-сборке.
- UI запускается по требованию: нет постоянного окна/иконки; память в фоне — только служба (~10 МБ).
- Один экземпляр-«источник правды» → нет гонок, дублей процессов и «кто кого перезапустил».

Headless TG WS Proxy: upstream 1.11.4 — Python/PyInstaller с треем. Собираем свою сборку из исходников
(форк Flowseal/tg-ws-proxy): убираем pystray/UI, оставляем CLI-режим (`console mode` уже есть в коде:
ветка `if pystray is None …`), собираем PyInstaller'ом → один exe без трея. Аргументы те же
(`--host --port --secret --buf-kb --pool-size --dc-ip`), значит Telegram настраивать заново не нужно.

## 4. Модель плагинов (компонентов)

Манифест `component.json` (наш формат, расширяет идею CDPI):

```json
{
  "id": "zapret2",
  "name": "Zapret2",
  "provider": { "type": "zip_bundle",
                "url": "https://github.com/bol-van/zapret-win-bundle/archive/refs/heads/master.zip",
                "root": "zapret-win-bundle-master/zapret-winws/" },
  "versioning": { "type": "bundle_master", "fingerprint": "sha256-of-winws2" },
  "install": { "target": "winws2.exe", "keep": ["lua/*"] },
  "run": { "exe": "winws2.exe", "args_template": "{profile_args}", "elevation": "system" },
  "health": { "process": "winws2.exe", "port_probe": null }
}
```

Провайдеры (типы источников):
- `github_release_asset` — последний релиз (TG WS Proxy `TgWsProxy_windows.exe`);
- `zip_bundle` — мастер-архив (Zapret2: `zapret-win-bundle`);
- `git_tag` — фиксированный релиз (конфиг-паки);
- `local` — вручную установленный компонент.

Каждая установка: скачать → проверить SHA256/подпись → распаковать в
`%ProgramData%\<app>\components\<id>\<version>` → атомарно переключить указатель `current` → сохранить
предыдущую версию для отката. Обновление **никогда** не затирает работающую версию: новая ставится рядом.

Учёт версий: `installed_version`, `fingerprint`, `last_check`. Повторная установка запрещена, если
fingerprint совпадает (это решает «при каждом запуске всё обновляется»).

## 5. Каталог стратегий и импорт

Единая схема:

```json
{
  "id": "zdy-alt/generalALT9",
  "name": "ALT9 (hostfakesplit, ts)",
  "engine": "winws2",               // winws1 | winws2
  "source": "cdpi/zapret-discord-youtube-alt",
  "filters": [
    {"proto":"tcp","ports":"80,443","hostlist":"list-general.txt",
     "exclude":["list-exclude.txt"],"args":["--lua-desync=...", "--out-range=a"]}
  ],
  "lists": { "list-general.txt": {"type":"inline|url","value":"..."} },
  "tags": ["youtube","discord"]
}
```

Импортёры:
1. **CDPI-паки** (`CSZTR1003`, `CSZEFL002`, `CSYOKS001`): формат `IC:v1.0`, `startup_string` с `%VARS%` →
   нормализуем в нашу схему; для legacy v1 запускаем движок `winws.exe` (не пересобирая в zapret2),
   для zapret2-конфигов — `winws2`.
2. **Zapret2 GUI** (`zapret-discordyoutube/zapretgui`): у них `src/app/feature_facades/presets.py` и
   `src/blockcheck/*` (движок автоподбора). Экспортируем их пресеты в наш JSON; сам движок не портируем,
   а вызываем как внешний инструмент (или реализуем свой тестер по их логике).
3. **Апстрим zapret2**: нативные конфиги и списки (`bol-van/zapret2`).

Списки (hostlist/ipset): единый менеджер — дедупликация, нормализация, лимиты, версии, привязка к
стратегии. Раздутые списки (527 тыс. строк) режем/помечаем как «широкие».

## 6. Автовыбор стратегии (то, что избавит от «переделываем одно и то же»)

- Встроенный тестер: для набора целей (youtube, discord, telegram, произвольные) запускает кандидата,
  измеряет TLS/черепаший отклик/скорость сегментов, фиксирует ошибки.
- Профиль сети (ISP, ASN, внешний IP) → результат кэшируется: «в этой сети лучше стратегия X».
- При старте: если сохранённая стратегия перестала проходить тест — берём следующую из каталога и
  предлагаем (или автоматически применяем) с откатом.
- Все результаты — в JSON, UI показывает историю.

## 7. Обновления и UX

- Проверка обновлений: при старте и раз в N часов (настраивается), а также «по кнопке».
- **UX как вы просили**: кнопка «Пуск» поднимает текущую версию **сразу**, обновление качается в фоне и
  применяется при следующем запуске (баннер «доступно обновление» → «применить и перезапустить»).
- Подпись манифестов (Ed25519) + SHA256 файлов — обязательно, если раздаём другим людям.
- Обновление самого приложения: Tauri updater (подписанные пакеты) или просто установщик поверх.

## 8. Один установщик и размеры

- NSIS-инсталлятор (Tauri генерирует): ~10–15 МБ, один `.exe`, ставит службу + UI.
- Portable-режим: тот же `.exe` рядом с флагом `portable.flag` → без службы, с UAC при запуске.
- Целевые цифры: служба ~10 МБ RAM, UI 60–120 МБ только когда открыт, установка ~30–40 МБ с компонентами.

## 9. Этапы

| Этап | Результат | Оценка |
|---|---|---|
| M0 | Каркас: UI + служба + IPC, «Запустить/Остановить winws2», профиль | 3–5 дней |
| M1 | Менеджер компонентов (манифесты, провайдеры, атомарные обновления, откат) | 4–7 дней |
| M2 | Headless TG WS Proxy как компонент (сборка без трея) | 2–3 дня |
| M3 | Каталог стратегий + импорт CDPI-паков | 5–8 дней |
| M4 | Импорт пресетов zapretgui + тестер/автовыбор | 5–8 дней |
| M5 | Установщик, portable-режим, подписи, автообновление приложения | 3–5 дней |

## 10. Риски

- Сборка WinUI/Avalonia из исходников CDPI — не нужна, если пишем своё (рекомендуется).
- Python-сборка headless TG-прокси: PyInstaller может тянуть лишнее; альтернатива — оставить upstream
  бинарник и запускать его в отдельной сессии (без трея), но это менее чисто.
- Тестер стратегий = самый «дорогой» модуль; начинать с простого (5 целей, 3 метрики).
- Юридически: Apache-2.0 у CDPI позволяет брать код/идеи с сохранением notices; upstream-компоненты
  (zapret, tg-ws-proxy) — под своими лицензиями, их распространяем как отдельные загрузки.
